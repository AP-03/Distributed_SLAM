# MESA Benchmark Tools

This directory contains the offline tools used to evaluate MESA as a
distributed pose-graph backend on the collected robot datasets.

The reportable pipeline is:

1. Export wheel odometry and mocap trajectories to TUM format.
2. Run a local RGB-D RTAB-Map frontend for each robot bag and export one g2o
   pose graph per robot.
3. Run AprilTag detection on each robot bag.
4. Infer robot-mounted tag targets from odometry/tag consistency, then generate
   inter-robot pose constraints from the accepted detections.
5. Build a multi-robot JRL dataset and run MESA.
6. Export MESA results to TUM and evaluate against mocap with the documented
   robot-label/time-offset mapping.

Ground truth is used only for evaluation and for estimating the robot-bag to
mocap-label/time mapping. It is not used to build MESA factors.

## Expected Dataset Layout

```text
runs/<scenario>/
  raw/
    mocap.bag
    robots/
      robot_01.bag
      robot_02.bag
      ...
  eval/
  processed/
```

## Environment

The scripts assume ROS Melodic and the local MESA/JRL/GTSAM build used during
the project:

```bash
source /opt/ros/melodic/setup.bash
source .venvs/eval/bin/activate
```

`evo` is used for APE/RPE summaries after the TUM trajectories have been
exported.

## Frontend + MESA Pipeline

Run the reportable frontend/backend chain:

```bash
RTABMAP_RATE=3 APRILTAG_RATE=4 \
  bash tools/mesa_benchmark/run_mesa_frontend_pipeline.sh \
  runs/<scenario> <robot_count> <run_name>
```

Outputs are written under:

```text
runs/<scenario>/processed/rtabmap_<run_name>/
runs/<scenario>/processed/graphs_<run_name>/
runs/<scenario>/processed/apriltag_constraints_<run_name>/
runs/<scenario>/processed/jrl_<run_name>/
runs/<scenario>/mesa2d/<run_name>/
runs/<scenario>/eval/tum/mesa_<run_name>/
```

The generated inter-robot constraints are in:

```text
runs/<scenario>/processed/apriltag_constraints_<run_name>/orkar_apriltag_mesa_inter_robot_constraints.csv
```

## Evaluation

First export mocap and robot odometry to TUM:

```bash
python tools/mesa_benchmark/export_bag_pose_tum.py \
  --bag runs/<scenario>/raw/robots/robot_01.bag \
  --topic /odom \
  --output runs/<scenario>/eval/tum/robot_01_odom.tum

python tools/mesa_benchmark/export_bag_pose_tum.py \
  --bag runs/<scenario>/raw/mocap.bag \
  --topic /gt/robot_01/odom \
  --output runs/<scenario>/eval/tum/mocap_robot_01.tum
```

Estimate robot-label/time mapping when clocks were not synchronized:

```bash
python3 tools/mesa_benchmark/orkar_tum_time_shift_sweep.py \
  --estimate-template 'runs/<scenario>/eval/tum/{robot}_odom.tum' \
  --gt-template 'runs/<scenario>/eval/tum/mocap_{gt}.tum' \
  --robots robot_01 robot_02 \
  --gt-labels robot_01 robot_02 \
  --out-dir runs/<scenario>/eval/time_shift \
  --name odom_to_mocap

python3 tools/mesa_benchmark/write_mapping_from_time_shift.py \
  --summary runs/<scenario>/eval/time_shift/odom_to_mocap_time_shift_summary.json \
  --output runs/<scenario>/eval/time_shift/odom_to_mocap_mapping.csv
```

Evaluate an exported method in the mocap frame:

```bash
python3 tools/mesa_benchmark/evaluate_tum_to_gt_joint.py \
  --mapping runs/<scenario>/eval/time_shift/odom_to_mocap_mapping.csv \
  --estimate-template 'runs/<scenario>/eval/tum/mesa_<run_name>/<dataset>_{robot}.tum' \
  --gt-template 'runs/<scenario>/eval/tum/mocap_{gt}.tum' \
  --method mesa_<run_name> \
  --output-dir runs/<scenario>/eval
```

For final tables, run `evo_ape` on the aligned TUM files generated by the
evaluation script and store the result zips/tables in `runs/<scenario>/eval/`.

## Utility Scripts

- `run_orkar_rtabmap_robot.sh`: runs the RTAB-Map RGB-D frontend for one robot.
- `run_apriltag_ros1_bag.sh`: runs `apriltag_ros` on one robot bag.
- `export_apriltag_detections.py`: flattens detection bags to CSV in the robot
  base frame.
- `orkar_apriltag_ros1_diagnostic.py`: scores tag IDs against candidate target
  robots using odometry consistency.
- `generate_orkar_apriltag_mesa_constraints.py`: converts accepted AprilTag
  detections into MESA inter-robot constraints.
- `export_jrr_tum.py`: exports MESA/JRL results to TUM trajectories.
- `diagnose_mocap_motion.py`: flags mocap jumps or pickup windows before
  evaluation.

## Non-Reportable Diagnostics

The reportable toolset excludes helpers that produce odometry-only MESA plots,
path-shape-only EVO numbers, or ground-truth/oracle inter-robot constraints.
Those can be useful during development, but they are not defensible benchmark
evidence for a distributed SLAM comparison.
